# MM_LLM UI 개편 — 중립색 기반 업무 공간

사용자 방향: 보라색을 제거하고, 정보 밀도와 구분이 명확한 현대적인 업무 도구로 개편한다. 기능 수를 늘리기보다 현재 기능을 찾고 읽고 조작하는 순서를 정리한다.

**v0.5.0 UI 개편의 구현 및 검증 기록**이다. 아래 이미지는 샘플 데이터와 격리된 미리보기용 bridge로 실행한 실제 Electron 렌더러 캡처다. 실제 API 호출이나 사용자 기록은 사용하지 않았다.

## 화면 구조

| 화면 | 변경 내용 |
| --- | --- |
| 로그인 | 학과 소개와 API 키 입력 영역 분리, 키 보기·숨기기 추가, 진단 버튼은 오류 발생 시 표시 |
| 사이드바 | 작업 공간·미디어·최근 대화 그룹, 상단 검색, 카드형 미디어 메뉴를 일관된 행으로 변경 |
| 접힌 사이드바 | 새 대화·검색·프로젝트·비교·챗봇·미디어·설정에 접근 가능한 아이콘 탐색 |
| 대화 | 상단은 제목과 모델에 집중. 웹 검색·사고 강도·설정을 입력창 안으로 이동 |
| 시작 화면 | 승인된 학과 카피 유지, 장식 아이콘 제거, 가로형 시작 가이드 4개 배치 |
| 모델 선택 | 모델명 중심 목록, 실제 모델 ID는 툴팁 및 검색으로 확인, 긴 목록 내부 스크롤 |
| 모델 비교 | 비교 작업에 맞는 제목, 접을 수 있는 실행 설정, 넓은 답변 열, 한글 상태 표시. 좁은 창에서는 답변을 세로로 배치 |
| 앱 설정 | 테마·글자·기본 지침을 먼저 표시, 백업·진단은 펼쳐서 사용 |
| 미디어 | 설명과 작업 설정·결과 영역을 구분하고 장식용 대형 소개 영역 축소 |

## 디자인 규칙

- 중립적인 회색·흰색 캔버스와 진한 본문 색, 선택 상태와 주요 동작에 파란색 사용.
- 다크 모드는 회보라색에서 차콜·슬레이트 계열로 변경. 초기 창 배경도 같은 색상으로 맞춤.
- 작은 반경과 일관된 메뉴 행으로 밀도를 높이고, 답변 본문은 읽을 수 있는 폭과 행간을 유지.
- 기존 최소 글자 크기, 색 대비, 포커스 표시, 동작 줄이기, 고대비 모드 규칙 유지.
- 창의 최초 세로 비율과 마지막 창 크기·위치 복원은 유지.

최근 디자인 시스템의 원칙 중 콘텐츠와 조작부의 계층 구분을 참고했다. MM_LLM에서는 이를 문서 중심 캔버스와 입력창 주변의 응답 설정으로 해석했다. [Apple 디자인 시스템 설명](https://developer.apple.com/videos/play/wwdc2025/356/), [Fluent의 반응형 레이아웃 원칙](https://fluent2.microsoft.design/layout).

## 검증

- `npm run build`: 타입 검사와 프로덕션 빌드 통과.
- `npm test`: 순수 로직 테스트 파일 23개와 UI DOM 테스트 35개 통과.
- `npm run ui:audit`: 대비 조합 68개와 기존 접근성 스타일 감사 통과.
- 새 회귀 테스트: 접힌 탐색 버튼에서 연 대화상자의 포커스 복귀 3건, 닫힌 상세 설정 내부를 건너뛰는 키보드 탐색 1건.
- Electron 렌더러에서 1280×900, 980×1180, 640×820 화면 및 라이트·다크·작게·크게 설정 조합을 표본 확인. 확인한 화면에서 문서 전체의 가로 넘침이나 오류 알림 없음.
- 위 검증은 Linux의 Electron 렌더러에서 수행했다. macOS·Windows 설치 환경의 모든 상태를 시각적으로 검증한 것은 아니다. 플랫폼별 빌드·패키지 검증은 [릴리즈 자동화](RELEASE_AUTOMATION.md)에서 수행한다.
